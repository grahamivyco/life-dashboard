# Life Dashboard

Graham Ivy's personal app. Live at https://grahamivyco.github.io/life-dashboard/ (installable on iPhone and Mac).

## Stack
- React + Vite (plain JSX), HashRouter, deployed to GitHub Pages by `.github/workflows/deploy.yml` on every push to `main`
- Supabase project `wruevdyyhuizyydibzar` (eu-west-3). Sign-in is a Supabase passkey (`signInWithPasskey`, Face ID / Touch ID; RP ID grahamivyco.github.io, synced by iCloud Keychain). Fallback is an emailed 6-digit code typed on the login screen (`verifyOtp`), so it works inside the home-screen app; the Magic Link email template must include `{{ .Token }}`. Auth email goes through custom SMTP (Graham's Gmail app password, set 2026-10-19; 30 emails/h). After any sign-in without a passkey, `BioLock` offers once to `registerPasskey()`; Settings can add one too. Settings also has an optional Face ID lock, asked once per device, then trusted until sign out (`src/biometric.js`, localStorage `bio-unlocked`). The lock reuses the Supabase passkey: never create a second, lock-only passkey (iPhone offers it at sign-in and Supabase rejects it with "incorrect UUID length"). Settings is a section at the bottom of Profile (`AppSettings` in `src/pages/Settings.jsx`, grouped rows with switches); `/settings` redirects to `/profile#settings`. The link in the same email uses PKCE and only works in the browser that requested it. Every table is owner-only via RLS, plus a restrictive `only graham` policy pinned to his user_id on every public table and `storage.objects` (add the same policy to any new table). The built app ships a Content Security Policy (`vite.config.js`): a new external script, API or frame host must be added there.

## Working rules
- Commit and push straight to `main` after every change (Graham wants it automatic and immediate). Run `npm run build` first.
- Concise UI copy. No em-dash asides, no hype words.
- When Graham asks for a UI change or idea, include screenshots of what it looks like:
  `node scripts/screenshot.mjs <name> <route> [...]` builds with sample data (`--mode demo`, `src/demo.js`), saves desktop + phone PNGs to `public/previews/<name>/`, and prints their live URLs. Commit them so the URLs work. Never screenshot real data.
- Page checker (scheduled 3x a day in the "Check my pages" thread): `node scripts/check-pages.mjs` loads every page with sample data at phone and desktop width and lists JS errors, sideways overflow, raw text like NaN/undefined, empty pages and broken images. `scripts/data-checks.sql` (run with Supabase execute_sql) lists stale snapshots, Finances tiles that don't match their transactions, money in filed as transfers, stalled or failed requests, and overdue open jobs. Add a route or a check there when a new page or bug type appears.
- Phone fields stay at 16px+ (rule at the end of styles.css) so iPhone doesn't zoom on tap.
- Phone must never zoom out or overflow sideways. After layout changes run `node scripts/phone-audit.mjs <routes>` (add `STRESS=1` to test long text); everything should print `ok` with no offenders.

## Design (Open Frame, refined)
- Cream page `#F3F1EA`, surface `#FFFDF8`, ink `#2F2C27`, muted `#77736A`, hairline `#E4E0D5`
- Brand colors, one meaning each (Graham, 2026-10-19): tomato `#F24333` = needs you (badges, alerts, active nav); blue `#2F6BF0` = where you are (active tab, selected menu row, chart lines, selected bar); green `#33AC66` = good / money in / done (`.num.pos`, progress, switches, paid); gold `#F4BF3A` = waiting (Pending, sent, applied). Soft tints (`--blue-soft` etc.) for pills and selected states; dark `-ink` variants for text. Stat tiles get a colored dot in the eyebrow. Use the tokens in `styles.css`, never a new color.
- Fraunces for page titles and big numbers, Inter 13–14px for everything else
- Icon rail menu that expands to labels on hover / tap of the mark. On phone (≤640px) it is replaced by `src/components/MobileNav.jsx` (after Muse, Graham 2026-10-19): top bar with a round menu button, the page title and the avatar (→ `#/profile`); the menu is a side drawer listing every page that pushes the page aside; the floating frosted bottom bar holds the current page's own tabs as icons. `<Tabs>` portals itself there on phone (`#m-tabs-slot`); `<Tabs phoneOnly>` puts a desktop ViewMenu's options there (Email Show, Housing Show, Today kinds, Timeline Show, Clients one at a time, Profile sections). Tabs need an `icon`; the bar is icons only (like Muse) and the top bar title shows the current tab (`title` overrides the label). Pages with no tabs show no bar.
- Tiles: 12px radius, 1px hairline, no shadows. Lists use collapsible rows with a chevron; delete/dismiss are icon buttons.
- Controls (`src/components/Controls.jsx`, Graham 2026-10-19): header is eyebrow + title only, no buttons. Under it one `<Controls>` row: `<Tabs>` (page sections, at most one row) and `ViewMenu`s on the left; `end` holds `RoundButton`s (refresh, sync, search) and at most one primary `.btn`. A range row uses the same `<Controls>`: `.range-nav` (‹ title ›) left, period `ViewMenu` at the end. Every control is a 36px airy pill (`--ctl`: faint border, soft shadow, fully round; menus are 20px-radius cards). Phone tab bar: frosted floating pill, current tab on a soft grey pill, no dot. Any view, filter, sort or period switch is a `ViewMenu` (one button showing what's on, tap for a list). A view with nothing shows `<Empty title>line</Empty>`; an empty list inside a tile uses `<p className="empty">`.

## Data
- `brain_dumps` → sorted by Claude into `items` (task/goal/idea/note) and `events`; set `processed_at`
- `items` insert trigger auto-queues tasks and ideas into `claude_requests`
- `claude_requests`: queued → working → needs_approval → approved → done/failed/dismissed. `links` is `[{title,url,image?}]`; `image: true` renders as a thumbnail. Today shows only what needs Graham: a "Needs your OK" list (hidden when empty) and a "Claude: done" pill on items with an unseen result, which opens inline and disappears once read. The sidebar badge counts approvals only.
- Ask Claude (`src/askClaude.js`): Email's help, translate and question boxes insert a `claude_requests` row with `action='ask'`; the hourly worker answers in `result`. The floating ✦ panel was removed (Graham, 2026-10-19) and `supabase/functions/ask-claude` is switched off (returns 410).
- `section_snapshots`: latest payload per section (`email`, `finances`, `housing`, `jobs`, `events`, `clients`, …) written by the hourly sync
- Email translation: non-English snapshot threads carry `lang`, `subject_en`, `message_en`, and each reply option a `tr: {en, es, ca}`. The page shows English with "Show original" and an English/Español/Català switch on the reply box. Typed text uses the browser's on-device Translator (`src/translate.js`), else goes to Ask Claude. The nav shows a dot (not a count) when "To reply" has emails.
- Email help: snapshot threads that ask Graham to do something carry `help: {title, steps[], doc?: {title, body}, links?}`, shown as a collapsible checklist on the email (ticks per device) with a Copy button for the doc. "Help me with this" inserts an `ask` row noted `email:<id>| Help me with this`; the sync adds `help` to that thread. The "To reply" filter (default) shows the same set in both views: threads with reply options not sent, skipped, or answered by Graham since.
- Finances on the server (2026-10-19): edge function `money` (`supabase/functions/money`: `core.js` = port of the Mac app's reports and edits, `sync.js` = Plaid + YNAB sync, `index.ts`). The whole Mac database lives as one JSON doc in `public.money_store` (version-checked saves); Plaid/YNAB keys and per-bank access tokens are in Vault as `money:<uid>:<name>` (read with service-role RPC `money_secrets`). Opening Finances calls `op:'sync'` (skipped if synced in the last 10 min), edits call `op:'action'` with the Mac API's method/path; both republish `money_snapshot`. Moved in once from the Mac with `python3 -m money --move-to-cloud` (RPC `money_move_in`), after which the Mac app stops syncing and publishing. Until `money_store` has a row, the page falls back to the Mac path below. Not built yet: linking or reconnecting a bank from the web (Plaid Link). Deploy with Supabase deploy_edge_function (all three files). `scripts/money-parity.mjs` compares the port with the Python payload.
- Finances (2026-10-19) come from the money app in `mac/` (Malcolm's Plaid app, runs on Graham's Mac; Apple Card via YNAB in `mac/money/ynab.py`). `mac/money/bridge.py` publishes every report to `public.money_snapshot` (one row, `payload` = {dashboard, net_worth, spending{"month:0"…}, budget, recurring, transactions (2 years, empty fields dropped), categories, rules, holdings, accounts}) through RPC `money_publish(p_key, …)`; the Mac authenticates with a key made on the Finances page (`money_keys` keeps its sha256). Edits on the page insert `money_actions` (method, path, body = the Mac app's local API); the Mac takes them with `money_take_actions`, runs them, and marks them done/failed with `money_finish_action`. Page: `src/pages/Finances.jsx` + `src/money.js` (tabs Overview (with Accounts at the bottom), Spending (with Recurring at the bottom), Transactions; Sync is an icon button beside the tabs); demo data `src/demoMoney.json`. The Era `finances` snapshot is no longer shown.
- `subscription_overrides` (name, hidden, amount): Graham's hide/amount fixes on top of the synced subscriptions list. Cancel links and steps live in `src/subscriptions.js`.
- Clients: `public.clients` (name, emails/keywords used to match mail, notes edited on the page). The `clients` snapshot is `{clients:[{id, summary, threads:[{id,from,subject,date,unread,needs_reply,url}], invoices:[{number,amount,date,status:sent|paid|disputed|paused,note,url}]}]}`; invoices are Open Frame LLC's Wave invoices found in email.
- Profile (`/profile`, `src/profile.js` `useProfile`): `public.profile` (name, tagline, photo_path, events {cats[]}) plus the private `profile` bucket (`<uid>/photo-*`, `<uid>/docs/*`). It is the one place to edit preferences: Jobs picks/info (`job_profile`), Housing specs (`housing_profile`, Housing shows a summary linking to `#/profile#housing`), Events categories (Explore starts filtered to them). Documents lists his uploads and the Jobs base docs. Avatar (`Avatar.jsx`) shows the photo in the rail and the phone tab bar.
- Housing snapshot: `{source:'idealista', search:{label,url}, listings:[{id, source ('idealista'|'fotocasa'|'habitaclia'|'pisos'|'badi'|'facebook'), street, area, district, price, prev_price?, beds, size_m2, floor, exterior, lift, balcony, terrace, ac, photo, url, first_seen, gone?, balcony_street?, tiles?, advertiser?, phone?, long_term?}]}` built from portal alert emails (last 30 days). `housing_profile`: one row per user, `specs` {max_price,min_beds,balcony,exterior,lift,ac,areas[]}
- Jobs (moved from the Job Hub artifact 2026-10-19): `public.jobs` (pk user_id+slug; status new/approved/applied/interview/offer/accepted/rejected/skipped, needs_you, waiting_on, asks + my_answers {index: text}, updates [{date,text}], docs [{label,path,save}], paste, actions, extra {digest:{n,date,thread_id,url}, prep, outreach, where}, decided/filling/applied/confirmed/followed_up/responded_at; realtime on) and `public.job_profile` (info pairs, picks, watchlist, weights, base_docs, search.instagram). PDFs in private bucket `job-docs` at `<uid>/<doc path>`; only base docs (`docs/base/`) and cover letters are stored (Graham, 2026-10-19), tailored resumes are not. Digest picks are jobs rows with `extra.digest`; the `jobs` snapshot now only carries the digest's intro/closing/also links. Apply/Skip/answers update the row and insert `claude_requests` (`action='job'`, `status='approved'`, note `job:<slug>| Apply|Skip|Answers: …`); Search inserts note `search| <query; filters; Instagram: @…>`. The hourly sync carries them out and writes results back to `public.jobs`.
- Events (`src/events.js` `useEvents`, `useUpcoming`): Google Calendar comes from the `events` snapshot (next 30 days, all calendars but US holidays), merged with `public.events` rows (brain dumps, added in the app or from Explore; deduped by gcal_id or same title and minute). A series repeating 3+ times a week (work blocks) is a `routine`: dashed card in the calendar, left out of Next up, the month grid and Today. The page mirrors Graham's Calendar artifact: Next up card, Calendar tab (day/week/month icons, ← range →, `?view=`) and Explore tab (`?tab=explore`: search, date and category filters over `payload.picks`, + adds a pick to `public.events`). Picks come from the artifact's db doc `cities/barcelona` and are carried forward by the hourly worker. Calendar dots: tomato for Graham's main calendar, ink tones for the rest. Today's "This week" uses `useUpcoming`.
- Email reply options: the sync adds `message` (their latest message) and `replies: [{label, body}]` to email snapshot threads that need an answer. Picking one fills the reply box. Send goes straight through Gmail when connected, otherwise it inserts a `claude_requests` row (`action='send_reply'`, `status='approved'`, body in `result`) that the next sync sends. The Email page opens on "To reply": one email at a time with the first option as the draft, the others on request, Send, Skip (remembered per device until a new message arrives) and a mic for dictation.
